# MiniMax-H3 制作 SOP：先选工作流，再准备、生成和验收

适用于人物短剧、美女/时装展示、宠物、风格化角色，以及明确选用的动作/舞蹈续接任务。基础设施步骤共用；模型、首帧、续接、裁帧和显存策略按选定方案执行。用户明确选择优先于默认方案。仅整理文档或分析问题不启动渲染。

## 1. 先选方案，避免把不同模型栈的参数混在一起

| 决策 | 当前默认：独立分段 Ref2VA + 首帧 | 专项：潜变量连续镜头 / 旧 V9、动作或舞蹈图 |
| --- | --- | --- |
| 何时选用 | 新的角色短片、人物/宠物短剧、写真展示；连续剧情也可独立分镜 | 用户明确选择旧工作流或潜变量续接；题材是“真人”“舞蹈”本身不等于选择旧图 |
| 每段输入 | 稳定的独立角色身份参考 + 本段 `MiniMaxH3AddGuide(frame_idx=0)` | 按所选图使用角色参考、原生音视频潜变量及相容的引导条件 |
| 后段衔接 | 同机位选上一段实际合适末帧；换机位根据实际结尾重新构图 | 同机位才沿用 MotionContext；换机位/场景应按该图重新建立条件 |
| MotionContext / JoinMatch | 不接入；不套用续接裁帧或开头静默区 | 按实际节点与版本配置；旧例为 22 帧重叠，裁帧和音频对齐必须与图一致 |
| 模型与采样起点 | 官方 Ref2VA INT8 + 官方 INT8 编码器，24 步，无 Turbo/Bunny/皮肤 LoRA，无 sigma-tail 修改 | 使用选定的整套模型、编码器、适配器和采样配置，不能只拷贝其中一个加速参数 |
| 显存 / 启动 | 默认动态显存，`--disable-mmap --disable-all-custom-nodes`；不加 `--fast` / `--highvram` | 按已验证图选择显存策略和插件；旧快速脚本的 `scheme_a` 属于这一类 |
| 重拍 / 续跑 | 重拍受影响段；若其末帧或声纹被后段使用，复核相关后段 | 保存并加载兼容的原生 AV latent，复核受影响的接力链 |

默认方案的完整图、固定版本、人物/美女/宠物差异化检查在已安装的 `minimax-h3-drama-producer` 的 `references/segment_workflow.md` 中。没有安装该技能时，不把本仓库 `workflow_v9_final.json` 当作默认图直接运行；应先按上表在项目内准备并检查独立分段图。

默认图中，身份图片接 `MiniMaxH3ReferenceToVideo`；场景单图只接 `MiniMaxH3AddGuide`。将 Add Guide 的 positive 输出接到 guider，采样器保留 ReferenceToVideo 的原始 joint latent。场景图没有自动获得 `<Picture N>` 标签。在已记录的 ComfyUI `51285bff5bdc618f5dbe821377bbcdc5f3e94ea7` 中，图片 Add Guide 输入为 `positive/latent/vae/image/frame_idx`，没有 `strength`；迁移版本前检查实际节点 schema。

[历史白皮书](minimax_h3_industrial_workflow_whitepaper.md) 和 [社区模型安装指南](minimax_h3_uncensored_comfyui_guide.md) 仅在选择对应方案后读取。它们的模型大小、速度、LoRA 权重、关键帧和“零穿帮”表述不构成新项目的通用保证。当前 SOP 负责流程与方案边界；具体执行图和节点版本负责接口契约。

## 2. 分镜和素材在开机前完成

- 在独立项目内保存身份图、首帧、分镜、提示词、配置和执行图。生产任务不改上游模板；用户明确要求维护 skill/仓库时可修改源文档。
- 从剧本或展示目的安排可见动作、听者反应、景别和结束状态。真人检查脸部比例、肤质、手部和服装；美女展示还检查妆发、姿态与展示重点；宠物检查口鼻、毛发、耳爪和物种解剖。保持身份不等于冻结表情或固定机位。
- 身份图负责角色特征，场景首帧负责本段构图与起始状态。保留已认可的身份图；新生成的场景图须再次对照。首帧比例匹配输出画布，身份图无需强制扩成横屏。`1344×768` 为 7:4，竖屏需单独准备画布与布局。
- 同场景后段承接上一段实际结果。预先安排自动末帧提取；若实际结尾需要重新创作首帧，先保存成果并释放 GPU，再做创作。
- 先验证关键动作或代表性衔接，再延长制作。检查参考图 → 场景首帧 → 视频开头 → 说话/动作峰值 → 结尾；人物、宠物和不同画风都不能只凭服装/毛色判断身份一致。

### 按内容选时长

先测自然对白（若有），加上动作、反应和收尾，再从 `F=17k+5` 选择帧数。24 fps 下的示例：

| 帧数 | 时长 | 用法 |
| --- | --- | --- |
| 90 / 124 | 3.75 / 5.17 秒 | 简短动作、反应或短句 |
| 141 / 158 | 5.88 / 6.58 秒 | 需要更多表演空间的短段 |
| 192 / 209 / 226 | 8.00 / 8.71 / 9.42 秒 | 较长对白或动作组合 |
| 243 / 294 / 345 / 362 | 10.13 / 12.25 / 14.38 / 15.08 秒 | 仅在当前栈的显存与质量验证后使用 |

独立分段保留完整段长；22 帧扣除只属于实际使用相应重叠的续接图。提示词时间戳不强制控制开口、动作或台词结束。不要把旧方案的“黄金时长”、1.1 秒闭口等待或 2 秒动作节拍套给所有影片。

## 3. 云端启动前检查，启动后尽快证明任务在工作

1. 在本地检查控制脚本环境、Drive 授权、后期工具和本批输出目录。首次缺少的大模型用 CPU 下载并持久化，确认选定模型清单后再启动 G4。
2. 分配实例后保存目标 endpoint、开始时间和服务端费率，立即 `colab dfs mount -s <session>`。`colab new` 本身不启动 Drive worker 所需的远端 `127.0.0.1:8012` 凭据服务。
3. **同步预检**凭据服务可返回非空 token，以及所需 Drive 路径/API 可访问。只记录检查结果，不输出 token。失败时释放并核验，不先放任后台任务运行。
4. 将当前方案实际需要的权重通过 Drive v3/HF 下载到本地 NVMe；避免 FUSE 上直接 mmap 和遍历大量插件小文件。校验模型清单和文件完整性。
5. 超过 15 秒的远程任务用 `nohup` 后台执行并写日志，以有超时的命令轮询。worker 负责状态和成果同步，watcher 负责启动期限、整体期限、终态报告与释放。
6. 本批 `status.json` 应在 **150–180 秒**内出现。旧批状态不算心跳；超时读取一次任务日志，报告错误并释放目标 GPU，不等完整渲染期限耗尽。

`scripts/launch_g4_comfyui_fast.py --profile scheme_a` 会选择旧 Singularity/Heretic 栈和 `--highvram --fast` 等启动配置，**不适合作为默认官方 INT8 图的启动器**。旧记录的 42.33 GB / 75.4 秒预热仅描述对应方案的一次测量；新项目按实际清单准备，不能用这个数字推断下载完成或渲染速度。

控制连接断开时，先通过 Drive v3 状态/成果确认 worker 是否仍运行，再决定恢复。连接错误不代表生成失败，不重复提交状态未明的任务。任务达到终止条件后保存已有成果并释放，不无限重试。

## 4. 按作品需要安排声音

- 有对白时，可先由 H3 生成角色首次声音，再从实际完整发声中提取干净样本给后续镜头参考；只接当前说话人的声纹。文本中的 Audio 标签必须对应真实连接，无音频输入时省略音频参考标签。
- 需要指定音色时，使用独立 TTS。`scripts/launch_cloud_tts_studio.py` 与 `scripts/run_cloud_tts_remote.py` 提供 Qwen/IndexTTS 路线；单独制作配音无需 ComfyUI 或视频权重。为视频生成声纹种子的 Qwen VoiceDesign 使用隔离子进程，输出 `32kHz PCM_16 Stereo` 后退出，再启动视频栈。
- 双 TTS 常驻服务是单独工作负载；不要求每次视频生成都同时常驻双 TTS。旧男女主角的音高区间、年龄和情绪向量仅是角色设定示例。
- 无对白的写真/展示片只安排所需环境声或音乐，不自动加入配音、说话动作和字幕。BGM 与声纹是不同输入角色，按选定图处理。
- 当声音引发动作，明确声源、可听见的时机、角色反应和随后对白，并验收成片因果顺序。后期挪动音效须记录为修正，不算原生生成已经成功执行。

## 5. 仅潜变量续接方案使用的额外步骤

- 在最初运行时保存兼容的原生音视频 latent；恢复前核对 checkpoint 类型、来源段、图版本和被接力的实际输出。根目录发行包提供 `scripts/resume_from_latent_checkpoint.py`；另一 V9 图使用自己的 `H3SaveAVLatent/H3LoadAVLatent`，不能假定不同节点的文件可互换。
- MP4 解码帧可作为独立段的静态首帧，但不能替代原生 AV latent 来声称无损运动续接。latent 保存也不保证新段动作或身份完全一致。
- 只有图确实使用 JoinMatch 时才调其参数。旧例 `tuning=manual, strength=0.35, min_excess=2.5, match_spread=False, match_detail=False` 是对照起点，复查颜色/对比度后决定；不要给独立分段补这个节点。
- 同机位接力检查重叠帧、音频起点、姿态、速度和切点；换机位重新建立条件。动作/舞蹈根据当前编排选择完成动作或身体分离的交接点，不强制套用旧格斗招式、140 BPM、固定运镜或 LoRA 权重。

## 6. 落盘、释放与本地后期

- 每段保存原始视频/音频、实际执行图、输入哈希、环境与运行记录。用 Drive v3 确认最终成果非零大小并完成完整性检查后尽快释放；本地下载和人工审片可在释放后继续。
- 核验成功的服务端响应中已无目标 endpoint。只有原本仅此一个实例时，账户汇总才应为 `Active assignments: 0`、`0.00 CCU/h`；保留其他工作会话。脚本打印成功或删除本地记录不构成释放证据。
- 结算分别报告服务端费率/余额、时长乘费率的估算和可获得的余额变化；余额扣款可能延迟，不把估算标成实扣。
- 本地先检查每段浮点音频峰值与对白电平，再转换 PCM16/AAC；必要时用静态增益留出余量。PCM 编辑用 `asetpts=N/SR/TB` 保持采样时间戳，并在编码后的母片逐段核对前后对白同步。
- 按真实完整对白制作字幕，复核 ASR 同音词；字幕不能掩盖漏说的内容。提示词声明不生成画面内字幕，字幕在后期制作。检查实际字体和画布，不能直接沿用横屏坐标压竖屏片或把人物卡挡在人脸上。
- 使用已安装制作 skill 的 `references/pitfalls_and_fixes.md` 按阶段检查 macOS 工具、字体、字幕脚本参数、音轨保留和同卷替换。根目录 `scripts/auto_subtitle_video.py` 是另一套字幕实现，使用前核对自己的接口、字体和布局。
- 验收外观、表演、连续性、声音与技术完整性；全片解码通过不能代替视觉/听感检查。没有试听或相关验收时明确记录，不作成功推断。
